# Day 3 (2026-11-18) 상태 벡터와 디랙 표기법

## 오늘 한 것

- 보통의 뽑기(확률 벡터)와 큐비트(상태 벡터)를 NumPy 배열로 나란히 만들어 비교 (`day03.py` 1~2번)
- 디랙 표기법으로 상태를 쓰고, 벡터를 정규화 (`day03.py` 3~4번)
- Qiskit `Statevector`로 같은 상태를 만들어 확인 (`day03.py` 5번)

## 개념 정리

1. 보통의 뽑기는 **확률 벡터**로 적는다. `[0이 나올 확률, 1이 나올 확률]`이다. 숫자는 0 이상이고 합이 1이다.
2. 큐비트는 **상태 벡터** `[a, b]`로 적는다. a, b는 **진폭**이다. 진폭의 크기를 제곱해야 확률이 된다.
3. 확률이 같아도 진폭의 부호나 방향이 다르면 다른 상태다. `[0.6, 0.8]`, `[0.6, -0.8]`, `[0.6, 0.8j]`는 확률이 전부 `[0.36, 0.64]`지만 서로 다르다. 확률 벡터로는 이 차이를 적을 수 없어서 상태 벡터를 쓴다.
4. **디랙 표기법**: `|0>`은 `[1, 0]`에, `|1>`은 `[0, 1]`에 붙인 이름표다. `| >` 모양을 켓이라고 부른다.
5. 모든 상태는 `a|0> + b|1>`로 쓸 수 있다. `0.6|0> + 0.8|1>`은 0.6 × `[1, 0]` + 0.8 × `[0, 1]` = `[0.6, 0.8]`이다.
6. 자주 쓰는 상태에는 이름이 있다. `|+>`는 `[0.707, 0.707]`, `|->`는 `[0.707, -0.707]`이다. `|0>`에 H를 걸면 `|+>`, `|1>`에 H를 걸면 `|->`가 된다.
7. **정규화**: 상태 벡터는 크기를 제곱한 값의 합이 1이어야 한다. 아닌 벡터는 자기 길이로 나누면 된다. `[3, 4]`를 길이 5로 나누면 `[0.6, 0.8]`이다.

## 뽑기 기계로 이해하기

| 용어 | 뽑기 기계로 보면 |
| --- | --- |
| 확률 벡터 | 기계에 적힌 확률표. 보통의 뽑기는 이것이 전부다 |
| 상태 벡터 | 큐비트의 설정값. 확률표에 방향(부호)까지 더 들어 있다 |
| 진폭 | 설정값의 숫자 하나. 제곱해야 확률이 된다 |
| 정규화 | 확률의 합이 100%가 되도록 설정값의 길이를 1로 맞추는 일 |

## 오늘 쓴 코드

| 코드 | 뜻 |
| --- | --- |
| `np.array([0.6, 0.8])` | 벡터 만들기 |
| `np.abs(v) ** 2` | 각 숫자의 크기를 제곱 (진폭을 확률로) |
| `0.6 * ket0 + 0.8 * ket1` | `0.6\|0> + 0.8\|1>` 만들기 |
| `np.linalg.norm(v)` | 벡터의 길이 |
| `v / np.linalg.norm(v)` | 정규화 |
| `Statevector.from_label("+")` | 이름으로 상태 만들기 (`"0"`, `"1"`, `"+"`, `"-"`) |
| `Statevector(v).is_valid()` | 상태가 될 수 있는 벡터인지 확인 |
| `Statevector(qc)` | 회로가 만든 상태 벡터를 측정 없이 보기 |
| `sv.probabilities()` | 측정 확률 |
| `sv.sample_counts(1000)` | 1,000번 측정한 것처럼 결과 뽑기 |

## 질문과 답

**Q1. 확률 벡터가 있는데 왜 상태 벡터가 따로 필요한가?**

확률만 적으면 `[0.707, 0.707]`과 `[0.707, -0.707]`이 똑같이 `[0.5, 0.5]`가 된다. 그런데 H를 걸면 앞의 것은 0만, 뒤의 것은 1만 나온다(Day 1, 2의 간섭). 결과가 다르니 다른 상태이고, 이 차이를 적으려면 부호와 방향이 들어 있는 진폭이 필요하다.

**Q2. `|0>`은 숫자 0과 같은 것인가?**

아니다. `|0>`은 "측정하면 항상 0이 나오는 상태"의 이름이고, 벡터로는 `[1, 0]`이다. 숫자 0이나 벡터 `[0, 0]`과는 다르다.

**Q3. 왜 `[3, 4]`는 상태가 아닌가?**

제곱의 합이 9 + 16 = 25다. 확률의 합은 1(100%)이어야 한다. 길이 5로 나눠 `[0.6, 0.8]`로 만들면 0.36 + 0.64 = 1이 된다.

**Q4. `[0.5, 0.5]`는 상태인가?**

확률 벡터로는 맞지만(합이 1) 상태 벡터로는 아니다. 제곱의 합이 0.25 + 0.25 = 0.5다. 반반인 상태는 `[0.707, 0.707]`이다.

**Q5. `Statevector(qc)`로 상태를 볼 수 있는데 측정은 왜 하나?**

상태 벡터를 직접 보는 것은 시뮬레이터에서만 된다. 실제 양자컴퓨터에서는 측정 결과(0 또는 1)만 얻을 수 있다.

## 실행 결과 (`day03.py`)

- 확률 벡터 `[0.5, 0.5]`와 `[0.36, 0.64]`는 합이 1.0
- 상태 벡터 `[0.6, 0.8]`의 확률은 `[0.36, 0.64]`. `[0.6, -0.8]`과 `[0.6, 0.8j]`도 확률은 같다
- `|+>`는 `[0.707, 0.707]`, `|->`는 `[0.707, -0.707]`
- `[3, 4]`의 길이는 5.0, 정규화하면 `[0.6, 0.8]`. `[1, 1j]`를 정규화하면 `[0.707, 0.707j]`
- `Statevector([0.6, 0.8]).is_valid()`는 True, `Statevector([3, 4]).is_valid()`는 False
- H를 건 뒤의 상태는 `[0.707, 0.707]`, H와 Z를 건 뒤는 `[0.707, -0.707]`
- `[0.6, 0.8]`을 1,000번 측정하면 0이 360번 근처, 1이 640번 근처 (실행할 때마다 조금 달라진다)
